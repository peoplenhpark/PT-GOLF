# PT & GOLF 현재 운영 기준

이 문서가 현재 구현·운영의 기준이다. 이전 HANDOFF 문서는 배경과 결정 이력을 보존하는 자료이며 현재 기능 명세로 사용하지 않는다.

## 상태

- 현재 공개 버전: v90 (2026-09-27 배포 완료). 코드 커밋 c6d524d406631d4656a2daa2cf9b46059556d91d. GitHub Actions 실행 36288651723의 verify/deploy 모두 성공했다.
- 공개 확인: https://peoplenhpark.github.io/PT-GOLF/?v=90#golf/videos . release.json/index/초안·라우팅·SW 파일 확인, 390px 공개 화면의 PT 새로고침 복원·가로 넘침 없음·페이지 스크립트 오류 0건 확인. 게시 방식을 GitHub Actions로 전환하여 검증 성공한 _site만 게시한다.
- 런타임: 빌드 도구가 필요 없는 HTML/CSS/JavaScript PWA, GitHub Pages 정적 호스팅.
- 릴리스 버전의 유일한 원본: `release.json`. `release-assets.js`와 URL 버전은 `node scripts/release.cjs`로 생성한다.
- 기본 운동/원칙: `data/seed.json`. PT 미디어 등록부: `js/exercise-media.js`. 골프 영상/주제: `js/golf-data.js`.
- 개인 운동 편집·메모·즐겨찾기, 캘린더, 골프 레슨·질문·영상 적용 메모는 이 기기의 저장소에 보존한다. 저장 실패와 읽기 실패를 정상 저장으로 표시하지 않는다.

## 유지할 사용자 결정

- 신규 PT 동작에는 `.cursor/rules/pt-media.mdc`에 따라 준비·동작 이미지 2컷과 회전·재생 가능한 3D를 코칭과 함께 제공한다.
- 골프에서는 제거된 이미지·3D를 되살리지 않는다. 과거 주소는 현행 영상/스윙 노트로 연결한다.
- 개인 스윙 노트는 혼자 연습한 감각이며 정답일 수도 아닐 수도 있다. 원본 영상·코치 레슨·개인 추정을 구분한다.
- 백업 UI는 사용자의 이전 요청으로 제거했다. 내부 전체 기록 복구 스키마/검증은 유지하되 백업 UI는 별도 요청 없이 되살리지 않는다.
- 제안사항은 대화창에 표기한다. 최신본 유지 과정에서도 작성 중인 입력과 개인 데이터를 보존한다.

## 검증·배포

1. `npm ci`로 lockfile에 고정된 개발 도구를 설치한다.
2. 기능·콘텐츠를 수정하고 릴리스 시 `release.json`의 버전을 한 번 올린다.
3. `npm run release:prepare` → `npm run validate`를 실행한다. Node 검사는 브라우저나 개인 저장소에 쓰지 않는다.
4. `npx playwright install chromium` 후 `npm run test:browser`로 격리된 브라우저에서 검사한다.
5. `npm run build:site`는 `_site`에 필요한 런타임 파일만 복사한다. 골프 퇴역 엔진, 개인 작업 문서, 테스트와 개발 도구는 게시하지 않는다.
6. GitHub Pages의 Source를 **GitHub Actions**로 설정한다. `.github/workflows/pages.yml`은 Node 검증·브라우저 검사 성공 후에만 생성된 `_site`를 배포한다. branch 배포를 유지하면 이 게이트가 게시를 막지 못한다.
7. 배포 완료는 워크플로 성공과 공개 버전/대표 동작을 확인한 뒤 기록한다.

## 오프라인·업데이트 계약

- 기본 앱 셸과 텍스트 데이터만 설치 시 캐시한다. 운동별 이미지·3D는 사용자가 선택한 운동에 대해 준비한다. YouTube 원본 영상은 오프라인으로 저장하지 않는다.
- 캐시 키는 앱 내 정적 경로로 통일하며, timestamp/version 쿼리만 다른 데이터가 반복 저장되지 않는다. 다른 앱의 캐시는 삭제하지 않는다.
- 현재 워커에 저장된 HTML·JS·CSS는 함께 같은 릴리스로 제공한다. seed만 네트워크 우선으로 갱신하며, 4초 제한과 서버 5xx 오류 시 현재 캐시 자료로 대체한다. 최신 릴리스는 새 워커 설치·안전한 활성화·새로고침으로 적용한다.
- 릴리스가 바뀌면 준비했던 운동 ID를 새 릴리스 자산으로 다시 준비한다. 이관 중 네트워크 오류가 나면 최신 과거 캐시 1개를 재시도용으로만 남기며, 화면과 준비 상태는 현재 릴리스 캐시만 사용한다. 따라서 과거에 준비한 운동도 새 버전 자산이 모두 준비되기 전에는 미준비로 표시될 수 있고, 연결 복구 후 다시 준비해야 한다.
- Service Worker 업데이트는 대기하고 화면의 초안 보호가 완료된 뒤 `PTGOLF_SKIP_WAITING`으로 활성화한다.
- 선택 운동 준비: `PTGOLF_PREPARE_OFFLINE` + `exerciseIds` + `requestId`; MessageChannel 응답은 `PTGOLF_OFFLINE_RESULT`, `ok`, `cached`, `failed`, `exerciseIds`이다.
- 준비 상태: `PTGOLF_OFFLINE_STATUS`; 응답은 `readyIds`, `missingIds`이다. 운동 ID는 미디어 등록부의 유효한 PT 항목만 허용한다.

## 기록과 테스트 구분

- `docs/AGENT_HANDOFF.md`, `docs/PT_GOLF_VER1_3_HANDOFF.md`, 루트와 docs의 `HANDOFF.md`는 역사 자료이다. 맨 위의 현행 아님 안내를 유지한다.
- 현행 Node 게이트와 브라우저 검사의 범위는 `tests/README.md`를 따른다.
- 골프 퇴역 엔진과 관련 테스트는 Git에서 보존하되 현행 배포·필수 검사에 포함하지 않는다. 과거 주소를 위한 HTML redirect는 게시한다.

## v90 반영 범위 · 2026-09-27

- 개인 메모·즐겨찾기와 기본 설명을 필드 단위로 분리했다. 기존 전체 객체 편집은 legacyIds로 표시하고 원래 내용 전체를 보존한다. 출처가 불명확한 예전 편집을 자동으로 기본값으로 바꾸지 않는다.
- Persistence가 저장 성공 후 상태를 확정하며 손상 원본 덮어쓰기, 다른 탭의 같은 필드 충돌을 차단한다. 독립 변경은 병합한다.
- 운동·캘린더·골프·초안·테마를 포함하는 복구 스키마와 중단 복원 journal을 제공한다. 일반 백업 메뉴는 추가하지 않으며 오류 상태에서만 원본 복구 사본과 중단 복원 복구 안내를 표시한다.
- 메모·골프 양식·동작 편집의 초안을 보존하고, 현재 입력 또는 저장되지 않은 메모리 초안이 있으면 업데이트 재로딩을 미룬다.
- PT·검색·캘린더·골프의 주소와 세션 이동 범위·검색 조건·스크롤을 복원한다. 하단 오른쪽 뒤로/앞으로 위치를 유지한다.
- 최근 영상은 0편이어도 조회 기간과 공개일 기준을 표시한다. 38편은 고유 영상 수이며 최근 구획은 아래 그룹의 중복 노출임을 안내한다.
- 모바일 병렬 카드에서 제목에 전체 폭을 제공한다. 개인 스윙 감각, 제목·메타데이터 확인, 시범 관찰, 자막·화면 정리의 근거 수준을 구분한다.
- 관련 영상은 명시된 클럽·주제·직접 연결 레슨 근거로 최대 5편과 이유를 표시한다. 기존 영상 원문과 seed는 유지했다.
- 통합 검색은 운동·영상·레슨·내 노트의 보이는 필드를 검색하며 범위·일치 이유를 표시한다.
- 조작 영역을 실제 링크·버튼·체크박스로 바꾸고 팝업의 포커스 진입/닫기/복귀와 키보드 순환을 구현했다.
- 라우팅·초안·대화상자·검색·오프라인·업데이트를 작은 별도 모듈로 나눴다. 앱 실행에는 프레임워크나 별도 서버가 필요 없다.

### 검증과 한계

- Node 검증 9개 파일: 골프 데이터/가독성, 저장 16개, 초안·업데이트 8개, SW, PT 자세 검사.
- 격리된 Chromium 브라우저: 새 설치, PT 및 검색 새로고침, 앞으로 이력, 스크롤 복원, 메모·편집 파트·영상 초안, 검색 복귀, 그룹 해제, 320/390/768px 가로 넘침, 선택 운동 오프라인 이미지·3D, 골프 모듈 실패 시 PT 사용.
- 실제 사용자 브라우저 저장값에는 테스트 기록을 쓰지 않았다. 실제 휴대폰·화면 읽기 도구 전수 검사는 수행하지 않았다.
- localStorage는 원자적 다중 탭 트랜잭션을 제공하지 않는다. 최신 값 3-way 병합과 저장 전후 비교로 충돌을 보호하지만 극단적으로 동시 실행되는 쓰기를 완전히 직렬화하는 시스템은 아니다.
- 기존 legacy 편집을 자동 해제하지 않으므로 예전에 전체 객체로 저장된 항목의 설명은 계속 보존된다. 새로 저장하는 메모와 즐겨찾기는 최신 기본 설명을 가리지 않는다.
- 같은 기기 내부의 복구 사본은 외부 백업과 다르다. 일반 백업 UI 재도입과 다기기 동기화는 이번 범위에 포함하지 않는다.
