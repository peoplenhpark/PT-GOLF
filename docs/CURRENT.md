## 유지할 사용자 결정

- 관리 목표는 자료 수가 아니라 ‘혼자 할 수 있는지 / 잘못됐을 때 알아차리는지 / 다음 수업에서 질문을 해결하는지’다. 2026-10-09 기준 PT는 약 7~8회 남았으므로 종료 후에도 사용하는 개인 운동 기준을 축적한다. 골프에도 같은 원칙을 적용하되 남은 레슨 횟수를 임의로 가정하지 않는다.
- PT·골프의 기본 입구는 ‘지금 할 것 / 내 기준’ 두 곳이다. 원본 설명·부위 목록·레슨·감각·영상·5구 비교는 보조 경로로 보존한다. 새 자료를 현재 과제로 자동 채택하거나 개인 확인 표시를 코치 승인·숙련 판정으로 해석하지 않는다.
- 운동·운동 영상은 기본 PT이며, 사용자가 HT라고 명시한 자료만 HT로 분류한다. 골프 지정·기존 골프 문맥은 유지한다.
- HT에도 준비·동작 이미지 2컷과 회전·재생 가능한 전용 3D를 제공한다. 예시 설정과 개인 수업 실측값을 구분한다.
- HT는 PT와 같은 부위별 목록·상세·편집·즐겨찾기·메모를 제공한다. 관련 PT 운동을 기존 ID로 양방향 연결하고, 각 운동의 기록과 코칭은 별도로 보존한다. HT 영상 요약은 개인 PT 수업 기록과 구분한다.

- 신규 PT 동작에는 `.cursor/rules/pt-media.mdc`에 따라 준비·동작 이미지 2컷과 회전·재생 가능한 3D를 코칭과 함께 제공한다.
- 골프 3D는 되살리지 않는다. 2026-10-05 사용자 승인에 따라 영상에는 원본 장면 2컷과 시점 링크를 제공한다. 과거 주소는 현행 영상/스윙 노트로 연결한다.
- 개인 스윙 노트는 혼자 연습한 감각이며 정답일 수도 아닐 수도 있다. 원본 영상·코치 레슨·개인 추정을 구분한다.
- 운동·스윙 노트·영상 삭제 요청은 기기에서 즉시 숨긴다. 삭제·수정은 사용자가 변경 건을 선언했을 때만 처리하고, 매 배포마다 목록을 조회하거나 여부를 묻지 않는다. 명확한 대상과 내용을 이미 받았다면 재확인하지 않으며, 불명확한 내용만 질문한다. 앱 수정은 기기에 저장되고 공개 원본 변경은 전달받은 내용에 따라 반영한다.
- 백업 UI는 사용자의 이전 요청으로 제거했다. 내부 전체 기록 복구 스키마/검증은 유지하되 백업 UI는 별도 요청 없이 되살리지 않는다.
- 제안사항은 대화창에 표기한다. 최신본 유지 과정에서도 작성 중인 입력과 개인 데이터를 보존한다.
- 골프의 최근 7일은 YouTube 공개일이 아니라 앱에 처음 등록한 시각 기준이다. 중복 링크를 다시 받아도 최초 등록일과 기존 개인 기록을 유지한다.
- 골프 영상 즐겨찾기와 사용자 수정은 기기에 저장한다. 원본 영상 ID를 유지하고 기본 내용 복원 시 메모·상태·즐겨찾기를 보존한다.
- PT의 `입체로 자세 보기`는 열면 0.5배 느린 속도로 자동 재생하며, 사용자가 일시정지·속도·시점을 직접 바꿀 수 있다.

## 검증·배포

1. `npm ci`로 lockfile에 고정된 개발 도구를 설치한다.
2. 기능·콘텐츠 수정 시 캐시용 `release.json.version`을 갱신할 수 있지만 화면 표시 `displayVersion`은 유지한다. 첫 배포는 `1.0`; 이후 배포 준비 때 직전 성공 배포의 표시 버전에서 0.1만 올린다(1.9 다음은 2.0). 같은 배포의 수정·실패 재시도에는 표시 버전을 다시 올리지 않는다.
3. 사용자가 삭제·수정 건을 선언한 경우에만 해당 변경을 처리한다. 삭제 도구는 필요한 해당 건에 한해 수동 사용한다. 평소에는 `npm run release:prepare` → `npm run release:preflight`를 실행하며 중앙 삭제 목록은 조회하지 않는다.
4. `npx playwright install chromium` 후 `npm run test:browser`로 격리된 브라우저에서 검사한다.
5. `npm run build:site`는 `_site`에 필요한 런타임 파일만 복사한다. 골프 퇴역 엔진, 개인 작업 문서, 테스트와 개발 도구는 게시하지 않는다.
6. GitHub Pages의 Source를 **GitHub Actions**로 설정한다. `.github/workflows/pages.yml`은 Node 검증·브라우저 검사 성공 후에만 생성된 `_site`를 배포한다. branch 배포를 유지하면 이 게이트가 게시를 막지 못한다.
7. 배포 완료는 워크플로 성공과 공개 버전/대표 동작을 확인한 뒤 기록한다.

## 오프라인·업데이트 계약

- 기본 앱 셸과 텍스트 데이터만 설치 시 캐시한다. 운동별 이미지·3D는 사용자가 선택한 운동에 대해 준비한다. YouTube 원본 영상은 오프라인으로 저장하지 않는다.
- 캐시 키는 앱 내 정적 경로로 통일하며, timestamp/version 쿼리만 다른 데이터가 반복 저장되지 않는다. 다른 앱의 캐시는 삭제하지 않는다.
- 현재 워커에 저장된 seed·HTML·JS·CSS는 함께 같은 릴리스로 제공한다. 새 seed와 PT 미디어 등록부는 대기 중인 새 워커의 검증·안전한 활성화가 끝난 뒤 함께 적용한다. 이로써 이전 코드가 새 동작 데이터만 먼저 읽는 혼합 상태를 막는다.
- 릴리스가 바뀌면 준비했던 운동 ID를 새 릴리스 자산으로 다시 준비한다. 이관 중 네트워크 오류가 나면 최신 과거 캐시 1개를 재시도용으로만 남기며, 화면과 준비 상태는 현재 릴리스 캐시만 사용한다. 따라서 과거에 준비한 운동도 새 버전 자산이 모두 준비되기 전에는 미준비로 표시될 수 있고, 연결 복구 후 다시 준비해야 한다.
- Service Worker 업데이트는 대기하고 화면의 초안 보호가 완료된 뒤 `PTGOLF_SKIP_WAITING`으로 활성화한다.
- 선택 운동 준비: `PTGOLF_PREPARE_OFFLINE` + `exerciseIds` + `requestId`; MessageChannel 응답은 `PTGOLF_OFFLINE_RESULT`, `ok`, `cached`, `failed`, `exerciseIds`이다.
- 준비 상태: `PTGOLF_OFFLINE_STATUS`; 응답은 `readyIds`, `missingIds`이다. 운동 ID는 미디어 등록부의 유효한 PT·HT 항목만 허용한다.
