# 중앙 원본 삭제 요청

앱에서 기본 운동·스윙 노트 또는 골프 영상의 **원본 삭제 요청**을 선택하면 GitHub의 요청 작성 화면이 열립니다. 로그인 후 사용자가 직접 제출해야 중앙 목록에 접수됩니다. 앱에서 GitHub로 자동 전송하거나 즉시 공개 원본을 지우지 않습니다. 이 기기에서만 숨기기는 로컬 설정이며 이 목록과 별개입니다.

삭제 요청 접수만을 이유로 새 버전을 배포하지 않습니다. 기능 추가·콘텐츠 갱신 등 다음 배포가 있을 때 열린 요청을 함께 확인하고, 사용자가 승인한 항목만 원본 삭제와 함께 묶어서 반영합니다.

## 요청 형식

프런트는 아래 필드를 넣은 issue 작성 URL을 엽니다. `template=content-removal.md`와 함께 `title`, `body`를 URL 인코딩합니다. 대상은 기본 원본에 있는 ID만 허용하며 개인 추가 `usr_*` 운동은 중앙 삭제 대상이 아닙니다. GitHub 화면에서 마지막으로 **Submit new issue**를 눌러야 중앙 요청이 접수됩니다.

```text
<!-- pt-golf-deletion-request:v1 -->
content-kind: video
content-id: abcDEF_1234
<!-- /pt-golf-deletion-request -->
```

`content-kind`는 `video` 또는 `exercise`이고, 영상은 11자 YouTube ID, 운동은 `pt_*`/`golf_*` ID입니다. 사유는 표시 블록 밖에 적습니다. 검사기는 repo의 열린 issue만 읽으며 Pull Request, 닫힌 요청, 형식이 맞지 않는 본문을 승인이나 실행 명령으로 처리하지 않습니다. 라벨은 선택 사항이며 검사 권한이나 승인 근거가 아닙니다.

## 다음 배포 전 확인

```sh
npm run deletions:list
npm run release:preflight
```

공개 저장소 조회는 토큰 없이도 가능합니다. API 호출 제한 또는 비공개 접근이 필요한 환경은 `GH_TOKEN` 또는 `GITHUB_TOKEN`을 사용합니다. 토큰을 파일·issue·대화에 기록하지 않습니다. 조회 실패 시 확인 없이 배포하지 않습니다.

유효한 열린 요청은 아래 두 조건을 **모두** 만족해야 배포를 통과합니다.

1. 실제 사용자에게 대상 종류·ID·전체 원본 삭제 범위를 확인받고 `.github/deletion-approvals.json`에 동일 issue/종류/ID와 승인 시각을 기록한다. 요청 접수나 AI 추정만으로 승인 기록을 만들지 않는다.
2. 확인된 원본을 seed 또는 골프 영상 데이터에서 제거하고, 관련 그룹·직접 연결·대표 영상·검사 및 필요한 미디어를 함께 정리한다. 개인 메모·캘린더·즐겨찾기 데이터는 임의로 지우지 않는다.

승인 기록 예시(형식 설명일 뿐 실제 승인이 아님):

```json
{
  "approvals": [
    { "issue": 123, "kind": "video", "id": "abcDEF_1234", "approvedAt": "2026-09-27T03:00:00Z" }
  ]
}
```

승인 기록만 있고 원본이 남아 있거나, 원본은 없어도 승인 기록이 없으면 검사는 실패합니다. 승인된 수정과 검증을 반영한 뒤 issue를 닫습니다. 잘못된 대상이나 거절된 요청은 이유를 기록하고 닫아 처리합니다. 검사기는 issue를 수정하거나 닫거나 원본을 자동 삭제하지 않습니다.

승인된 원본이 빠진 새 버전을 기기가 받으면 해당 기기의 대기 요청은 자동으로 `completed` 상태가 되어 요청 목록에서 사라집니다. 개인 메모·레슨 기록은 계속 보존됩니다.

## CI

Pages 워크플로는 검증 시작 시와 배포 직전에 열린 요청을 다시 확인합니다. 두 검사 중 하나라도 실패하면 배포하지 않습니다. 배포 직전 조회 이후 생성되는 요청은 다음 배포에서 검사됩니다. 일반 오프라인 단위 검사인 `npm run validate`는 네트워크를 호출하지 않으며, 온라인 요청 확인은 `release:preflight`와 CI가 담당합니다.
