## 3. 반드시 보존할 사용자 결정

- 신규 PT 동작은 코칭과 함께 준비·동작 이미지 2컷과 회전·재생 가능한 3D를 같은 작업에서 완성한다. 기존 PT를 교정할 때도 이미지·3D·캡션을 최신 코칭과 일치시킨다.
- 기존 운동 ID를 유지해 메모·즐겨찾기·사용자 편집·삭제 요청 연결을 보존한다.
- 골프에서 제거된 이미지·3D를 되살리지 않는다. 골프는 원본 영상, 실전 요약, 개인 스윙 노트와 레슨 기록을 중심으로 유지한다.
- 개인 스윙 노트는 사용자가 혼자 연습하며 느낀 감각이므로 정답으로 단정하지 않는다. 원본 영상에서 확인한 사실, 코치 레슨, 편집자 관찰, 개인 추정을 구분한다.
- 확인하지 못한 중량·각도·기구명·영상 내용을 임의로 채우지 않는다.
- 골프 최근 7일은 YouTube 공개일이 아니라 **앱 최초 등록 시각** 기준이다. 같은 링크를 다시 받아도 최초 등록일과 기존 개인 기록을 유지한다.
- 골프 영상 즐겨찾기와 사용자 수정은 기기 저장소에 보존한다. 기본 내용 복원 시 영상 메모·적용 상태·즐겨찾기를 지우지 않는다.
- PT의 `입체로 자세 보기`는 열면 기본 0.5배 `느리게`로 자동 재생한다. 재생·일시정지·속도·시점·동작 슬라이더는 사용자가 바꿀 수 있다.
- 삭제 버튼은 운동·영상의 상세 화면에 한 개만 둔다. 요청 직후 해당 기기에서 숨기되 삭제 요청만을 위한 새 배포는 만들지 않는다.
- 다음 기능·콘텐츠 배포 때 중앙 삭제 요청을 다시 읽고, 사용자가 정확한 항목명·ID를 확인한 요청만 승인 기록과 원본 삭제를 함께 반영한다.
- 백업 UI는 별도 요청 없이 되살리지 않는다. 내부 복구 스키마와 저장 실패 보호는 유지한다.
- 제안사항은 앱 화면에 섞지 않고 대화창에 명시한다.
- 최신본 적용 중에도 작성 중인 입력과 개인 데이터를 보존한다. 실제 사용자 브라우저 저장값에 테스트 데이터를 쓰지 않는다.

## 4. v96에서 확정된 최신 기능

- 골프 영상 상세에 즐겨찾기와 수정 버튼이 있다. `★ 즐겨찾기` 목록에서 선택한 영상만 모아 볼 수 있다.
- 영상 이름과 `원본에서 볼 것`, `내 영상과 비교`, `레슨에서 확인`을 기기에서 수정할 수 있다. 원본과 다른 필드만 저장한다.
- 골프 목록·상세에서 반복 근거 배지, 장문의 시스템 설명, 저장 위치 각주와 중복 YouTube 안내를 줄였다. 개인 감각과 근거 한계에 필요한 문구는 유지한다.
- `pt_uprightrow` ID는 현재 **해머 스트렝스 아이소-레터럴 D.Y. 로우**다. 첨부 사진의 명판과 제조사 자료로 이름을 확인했고, 언더핸드 그립·머리 위 피벗·기울어진 시트와 가슴 패드·좌우 독립 레버를 준비/동작 2컷과 전용 3D에 반영했다.
- D.Y. 로우의 실제 사용 중량은 확인되지 않았다.
- `pt_dumbbell_rdl`은 덤벨 한 개를 양손 성배 그립으로 턱밑까지 올렸다가 몸 중앙선으로 내리는 양발 동작이다. v96에서 동작 이미지와 3D의 최저 골반을 더 낮췄다.
- v96 공개 Chrome 320·390·768px에서 D.Y. 로우 이미지 2장·전용 3D 62개 메시·0.5배 자동 시작, RDL 최저 골반 높이 0.76, 골프 즐겨찾기·수정, 가로 넘침과 브라우저 오류 0건을 확인했다.
- v96 기준선은 현행 Node 검사 16개, JavaScript 문법 검사 17개, 브라우저 스모크, 상세 54개·이미지 100장·3D 모델 50개 전수 시각 검사다. 셸 자산 21개, 운동별 오프라인 번들 50개, 게시 런타임 177개를 생성했다. 세부 결과는 `docs/visuals/verification.json`과 `tests/README.md`에 있다.

## 5. 개인 데이터와 콘텐츠 계약

- 기본 seed와 기기 저장 오버레이를 병합한다. seed 갱신으로 개인 메모·즐겨찾기·편집·레슨·질문·적용 상태를 덮어쓰지 않는다.
- 개인 저장 구조를 바꿀 때는 이전 스키마의 유효 데이터를 보존하고 손상 원본을 정상값으로 덮어쓰지 않는다.
- 골프 제목·실전 요약 편집은 `videoNotes[id]`에 원본과 다른 값만 저장한다. 즐겨찾기 해제나 기본 복원 뒤 빈 오버레이는 제거한다.
- 중복 YouTube ID를 새 영상으로 만들지 않는다. 기존 영상 ID·최초 등록 시각·메모·레슨 연결을 유지한다.
- 새 PT 항목은 `data/seed.json`과 `js/exercise-media.js`를 양방향으로 맞추고 준비·동작 이미지 2장과 3D 포즈·기구를 함께 등록한다.
- 이미지 생성 프롬프트·사용자 제공 참조·외부 근거·변환 기록을 `docs/visuals/`에 남긴다.

## 6. 오프라인과 업데이트 계약

- 기본 앱 셸과 텍스트 데이터만 설치 시 캐시한다. 운동 이미지·3D는 사용자가 선택한 운동에 대해 준비한다. YouTube 원본은 오프라인 저장하지 않는다.
- seed·HTML·JavaScript·CSS는 같은 릴리스의 서비스 워커에서 함께 제공한다. 이전 코드가 새 seed만 먼저 읽는 혼합 상태를 만들지 않는다.
- 릴리스가 바뀌면 선택 운동 미디어도 새 릴리스 자산으로 다시 준비한다.
- 대기 중인 서비스 워커는 작성 중 초안 보호가 끝난 뒤 활성화한다. 사용자의 저장되지 않은 입력 때문에 업데이트 재로딩이 미뤄질 수 있다.
- 캐시는 이 앱의 네임스페이스와 정규화된 경로만 다룬다. 다른 앱 캐시를 삭제하지 않는다.

## 7. 변경·검증·배포 절차

1. `git status -sb`, `git log -3 --oneline`, `release.json`, `docs/CURRENT.md`를 확인한다.
2. 현재 요청과 관련된 seed·미디어·저장·화면 코드를 함께 읽고 기존 ID와 개인 데이터 영향을 판단한다.
3. 실제 제품 릴리스 직전에 `npm run deletions:list` 또는 `node scripts/deletion-requests.cjs list`로 중앙 삭제 요청을 확인한다.
4. 제품 변경에만 `release.json`을 한 번 올린다. 핸드오프·운영 문서만 바꿀 때는 앱 버전을 올리지 않는다.
5. `npm run release:prepare` 또는 `node scripts/release.cjs`로 버전 참조와 자산 목록을 생성한다. 생성 파일을 수작업으로 맞추지 않는다.
6. `npm run release:preflight`를 실행한다. `npm`을 사용할 수 없고 의존성이 이미 준비된 환경에서는 삭제 검사 후 `node scripts/validate.cjs`를 실행한다.
7. `npm run test:browser` 또는 `node tests/browser-smoke.cjs`로 격리된 Chromium 회귀 검사를 실행한다.
8. `npm run build:site` 또는 `node scripts/site.cjs`로 `_site`를 만든다.
9. `git diff --check`, 의도한 파일 목록, 버전·seed·미디어 연결을 확인한다.
10. 정상 `main` push 뒤 해당 커밋의 GitHub Actions verify/deploy 성공을 확인한다. 강제 push하지 않는다.
11. 공개 `release.json`, 대표 PT·골프 화면, 모바일 가로 넘침과 브라우저 오류를 확인한 뒤 `docs/CURRENT.md`에 증거를 기록한다.
