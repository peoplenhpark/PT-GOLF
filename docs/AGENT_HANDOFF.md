## 2. 사용자 확정 UI와 보존할 동작

전체 운동 상세 순서는 다음과 같다. 없는 필드는 생략한다.

1. 뒤로가기·운동명·카테고리 태그·갱신일·즐겨찾기/수정
2. 단계 키워드(골프), 스펙(중량/횟수/핵심), 준비 자세
3. **타깃 근육·움직임·느낌**
4. **준비/동작 2컷 이미지와 읽을 수 있는 텍스트 설명**
5. **“입체로 자세 보기” 버튼 하나** — 누르면 3D 펼침
6. 운동 중 핵심 체크리스트 → 잊지 말 것 → 해당 카테고리 원칙
7. **내 메모**와 편집 기능

지켜야 할 결정:

- 이미지와 3D를 추가하면서 하단 메모·원칙·기존 큐를 없애거나 요약본으로 대체하지 않는다.
- 그림 확대 방법 안내 문구, “입체로 자세 확인하기” 같은 부제, 3D 소개 설명은 별도로 넣지 않는다.
- **2컷은 브라우저 기본 전체 화면 핀치 확대**. viewport는 `user-scalable=yes, maximum-scale=5`. 과거 라이트박스는 사용자가 불편해해 원복했으므로 되살리지 않는다.
- **PT 3D 안에서는** 한 손가락/드래그 회전, 두 손가락/휠 확대. 앞·옆·뒤·처음 시점, 재생/일시정지, 동작 슬라이더, 속도, 기구 표시를 지원한다.
- 카테고리 칩은 **flex-wrap으로 화면 안에 줄바꿈**. 가로 스크롤 탭으로 되돌리지 않는다. 긴 칩의 ` · ` 구분은 두 줄 라벨로 표시한다.
- 본문 글자 확대는 `text-size-adjust:125%`. 예전 SVG 내부 글자1.3배 지침은 보관 SVG에만 해당하며 새 캡션은 HTML/CSS 텍스트다.
- 내보내기/가져오기 UI는 사용자 요청으로 제거했다. Store 내부 함수가 남아 있어도 UI를 다시 만들지 않는다.
- 홈 검색과 PT/골프/즐겨찾기 헤더 검색을 유지한다. 카테고리 태그를 눌러 해당 탭으로 이동하는 기능도 유지한다.
- 예전 **골프 그림 없음**, **뒤꿈치 받침 스쿼트 그림 불필요** 결정은 이번 **전체 운동** 적용 요청으로 변경됐다. 단, 골프 핵심 키워드 스트립은 그대로 유지한다.
- 3D를 닫거나 운동 상세를 나가면 iframe을 제거한다. 모든 모델을 홈에서 미리 실행하면 안 된다.

## 3. 데이터와 저장소 동작

`data/seed.json`의 구조:

```jsonc
{
  "version": 33,
  "updated": "...",
  "parts": [{ "id": "pt", "label": "PT", "icon": "🏋️" }],
  "principles": [{
    "id": "pr_xxx", "part": "pt", "scope": "등",
    "title": "...", "items": ["..."], "reminders": ["..."]
  }],
  "exercises": [{
    "id": "pt_xxx", "part": "pt", "category": "등", "name": "...",
    "spec": "중량 · 반복수 × 세트 또는 한 줄 핵심",
    "prep": ["준비 자세"], "steps": ["단계"],
    "focus": { "muscle": "타깃", "move": "움직임", "feel": "느낌" },
    "cues": ["운동 중 핵심"], "reminders": ["잊지 말 것"],
    "image": "docs/images/기존.svg",
    "memo": "", "favorite": false, "updated": "YYYY-MM-DD"
  }]
}
```

- **원본은 seed, 기기 편집은 localStorage**. `ptgolf_overlay_v1`의 `{overrides, deleted}`를 `Store.getAll()`에서 합친다. 서버 동기화는 없다.
- 브라우저 데이터 전체 삭제는 메모·즐겨찾기·개별 수정·캘린더를 잃을 수 있다. 단순한 구버전 문제를 해결하려고 localStorage 초기화/삭제를 실행하지 않는다.
- seed 항목은 기존 id를 유지한다. 같은 운동을 새 id로 다시 만들면 기존 메모/즐겨찾기와 분리된다.
- 사용자가 전체 운동 객체를 저장한 오래된 overlay도 있다. 이 경우 seed의 새 필드 일부가 기존 로컬 값으로 가려질 수 있다. 읽기 구조를 확인하고 사용자의 편집을 일괄 삭제하지 않는다.
- 시각 자료 registry가 있는47개는 `e.image`보다 2컷+3D가 우선한다. 사용자 추가 운동 등 registry가 없는 항목은 기존 focus/image 상세로 동작한다.
- `getPrinciple`은 같은 part 중 **카테고리 정확 일치 → scope="*"** 순서. 이 우선순위를 바꾸면 재활 등 전용 원칙이 가려진다.
- 검색은 여러 공백 단어의 AND. 이름·스펙·카테고리·prep·focus·steps·cues·reminders·memo를 모두 조회한다.
- 체크리스트 체크 상태는 해당 실행 중 메모리 상태이며 새로고침하면 초기화된다. 개인 메모와 혼동하지 않는다.
- 캘린더는 별도 localStorage에 예약/완료/휴무와 예약 시각을 저장한다.
- **최근 일주일 세션은 별도 운동 수행 로그가 아니라 `getAll()`의 `updated`를 날짜별로 집계한 화면이다.** 오늘 포함7일, 최신순, 해당 기간 항목이 없으면 섹션 자체를 숨긴다.
- 현재 `upsert`는 `updated`를 오늘로 바꾸고 메모·즐겨찾기 변경도 이를 사용한다. 따라서 로컬 메모/즐겨찾기 변경이 최근 날짜 목록에 영향을 줄 수 있다. 이는 기존 동작이며 이번 시각 자료 작업에서는 바꾸지 않았다.
- 녹취를 seed에 반영할 때는 운동의 `updated`를 **레슨 날짜**로 기록한다. 이미지·문서만 바꿨다고 모든 운동 날짜를 오늘로 바꾸지 않는다.

PT 카테고리 현재 순서: **등 / 팔 / 가슴 / 어깨 / 하체 / 하체 · 머신 / 일일 수행 / 하체 재활 · 일일수행2 / 코어 · 밸런스**. 골프는 드라이버·아이언이다. `추천운동`은 `코어 · 밸런스`로 통합/개명했다.

## 4. 2컷과 3D 구현을 수정하는 법

### 연결 구조

`js/exercise-media.js`의 `window.ExerciseMedia[exerciseId]`에는 `name, kind, captions, notes, focus, target, images, viewer`가 들어간다. 푸시다운은 기존 전용 함수/뷰어를 쓰므로 일부 필드 구성이 다르다.

- 앱: `focusHtml` / `exerciseMediaHtml` / `pushdownMediaHtml` / `bindExercise3D`.
- URL: `#exercise/<id>`. 잘못된 id는 정상 운동 화면으로 취급하지 않는다.
- 일반 iframe: `media/3d/viewer.html?exercise=<id>&v=51`.
- 푸시다운 iframe: `samples/pushdown-3d/viewer.html?v=52`.
- iframe 높이는 `ptgolf-viewer-height` 메시지로 전달한다. 부모는 **origin, source===해당 iframe.contentWindow, 유한한 높이**를 검증하며320~1400 범위로 제한한다.
- 3D는 로컬 `samples/pushdown-3d/three.min.js`(Three.js0.160.1)를 공유한다. MIT 라이선스 파일도 같은 폴더에 있다.
- `poses.js`는 Three.js에 의존하지 않는 좌표 함수다. x=좌우, y=위, z=앞, 단위는 미터. 관절·기구·카메라 기준점·동작 단계를 반환한다.
- `viewer.js`는 재사용하는 메시 풀로 인체와 기구를 그린다. 타깃은 붉게 표시하고 사용자 시점과 재생 상태를 관리한다.
- 확인용 `window.exerciseViewer.snapshot()`은 id/kind/phase/pose/yaw/distance/meshCount의 사본을 반환한다. 자동 검사에서 사용하며 사용자 데이터는 포함하지 않는다.
- 골프4개는 같은 스윙 엔진을 공유하되 클럽 길이·스탠스·클럽 헤드를 구분한다. 오른손잡이 예시다.

**주의:** registry의 `notes/focus/captions`는 seed와 별도로 저장된 제작 당시 문구다. seed나 로컬 메모를 바꾼다고 3D 설명·그림이 자동 재생성되지는 않는다. 새 녹취로 자세·큐를 바꾸면 **seed, registry 문구, 2컷, poses.js** 사이의 일치 여부도 확인해야 한다. 현재 메인 focus·체크·메모는 Store의 값을 계속 렌더한다.

### 유지해야 할 개인 코칭 변형

- **데드버그:** “끝까지 뻗지 말고 반쯤, 약40%만”. 허리가 뜨기 직전까지만, 배는 계속 조인 상태. 2컷의 움직이는 무릎도 굽힌 채로 짧게 표현했다. 초기 생성본의 과도한 뻗기를 교정했다. 40% 표시는 개인 관절 각도를 측정한 수치가 아니다.
- **SLR:** 들지 않는 다리는 무릎을 세우고 발로 지지. 드는 다리는 편다.
- **티밸런스:** 지지 다리와 뒤로 뻗는 다리를 곧게, 골반이 열리지 않게. 3D의 과한 무릎 굽힘을 보정했다.
- **덤벨 풀오버:** 무릎을 몸쪽에 당겨 고정한 변형. 임의로 양발 바닥 버전으로 교체하지 않는다.
- **이상근 스트레칭:** 앞다리를 벤치에 접어 올리고 뒷다리를 빼 상체를 숙이는 버전. 옛 바닥 figure-four가 기본이 아니다.
- **백 익스텐션+덤벨 로우:** 몸통을 일자 사선으로 버틴 채 덤벨을 수직으로 당기는 변형. 양쪽2컷 모두 몸통 일자를 유지하도록 재생성했다. 머리·시선은 아래로(9/1 교정이 이전 “머리 들기”보다 최신).
- **암컬:** 원판이 수직으로 오르는 코칭을 반영. 일반 반원 궤적만 구현하지 않는다.
- **머신 로우:** 발판에 다리를 올려 골반을 고정하는 해머 스트렝스 버전. 케이블 시티드로우와 별도 운동이며 기구도 구분한다.
- **레그 익스텐션:** 현재2컷/3D는 한 발 버전. 원문에는 양발/한 발 병행, 무릎을 골반 쪽으로 들어 올리는 느낌을 기록했다.
- **레그 프레스:** 넓은 스탠스와 안쪽 허벅지 감각. 생성 원본의 좌우를 뒤집어 준비→미는 동작 순서로 저장했다.
- **사이드 레터럴 레이즈:** 양팔을 어깨 높이까지만. 두 번째 컷에 양팔 전체가 보이도록 교정했다.
- **골프:** 골반 접기 → 백스윙 → 왼쪽 체중이동하며 손 내리기 → 채가 내려올 때까지 지연 → 몸통 회전/면 임팩트 → 팔 펴기/중심 확인. 어깨 턴 높이·머리/몸 중심에 관한 기존 설명도 유지한다.

모델은 관절 동작을 관찰하는 **단순화된 인체**다. 실제 사용자의 신체·기구 치수, 모션캡처, 임상적으로 검증된 개인 자세를 재현한 것은 아니다. 좌표 검사 통과를 모든 운동의 완벽한 생체역학 인증으로 표현하지 않는다. 개별 운동 후 사용자 피드백으로 교정하는 흐름을 유지한다.

## 5. 녹취록 반영 규칙

2026-08-11부터 트레이너가 바뀌었다. 새 트레이너는 중량보다 정렬·통제, 어느 근육을 어떻게 쓰고 느끼는지를 강조한다. 사용자도 **준비 자세 / 운동 중 핵심 / 중량·횟수**를 특히 중요하게 본다.

1. 파일명만 보고 반영하지 않는다. 날짜·내용·직전 입력과의 동일 여부를 먼저 확인한다. 사용자가 잘못 고른 동일 파일은 작업을 중지해 달라고 한 이력이 있다.
2. 타 회원 레슨이 함께 녹음될 수 있다. 주인 세션 종료 인사와 화자 전환 등을 확인해 다른 회원의 내용을 제외한다. 7/24 후반부에 이런 사례가 있었다.
3. 기존 id, prep/cues/reminders/focus/spec와 대조한다. 같은 말은 추가하지 않고 기존 문장을 고친다. cues↔reminders 사이 중복도 확인한다.
4. 상충하면 **최신 레슨 내용이 우선**이다. 수치도 최신으로 갱신한다. 동작 변형을 남길 때는 기본 자세와 구분하여 간결하게 적는다.
5. 사용자 최신 요청이 “보강”이면 보강, “전면 대체”이면 **그 세션에 나온 운동**의 코칭을 새 내용으로 대체한다. 과거의 대체 요청을 근거로 매번 전체 데이터를 무조건 덮어쓰지 않는다.
6. 신규 운동은 기존 운동과 다른 동작/기구인지 확인하고 카테고리를 선택한다. 기존 동작과 이름만 달리 중복 등록하지 않는다. 고블릿 스쿼트 명칭은 사용자가 확정했다.
7. `prep`=준비, `cues`=실행 핵심, `spec`=중량·반복수·세트, `focus`=근육·움직임·느낌으로 정리한다. 준비 필드가 없는 기존 운동은 새 녹취에 등장할 때 채운다.
8. 중요한 내용을 쉽게 강조하라는 요청은 상단 큐·focus·필요한 spec·2컷/3D까지 일관되게 반영한다. 데드버그40%가 대표 사례다.
9. `updated`는 해당 레슨 날짜로 기록하고 seed 버전을 갱신한다. 시각 자료/registry와 동작이 충돌하지 않는지도 확인한다.
10. 유사 문구 스캔은 후보를 찾는 보조 수단이다. 점수만 낮추려고 필요한 코칭을 삭제하거나 다른 의미를 합치지 않는다.

## 6. 자산 버전과 배포

현재 **N=53**. 앱/이미지/3D 변경 시 다음 버전은54이지만, 사용자가 그 사이 변경했을 수 있으므로 작업 시작 때 실제 파일을 확인한다.

함께 맞출 곳:

- `sw.js`의 `CACHE = 'ptgolf-vN'`와 ASSETS의 버전 쿼리.
- `index.html`의 **css/style.css, js/store.js, js/exercise-media.js, js/app.js** 쿼리4개.
- `js/app.js`의 `ASSET_VER`.
- `index.html`의 `css/golf.css`, `js/golf-data.js`, `js/golf.js` 및 SW ASSETS도 함께 갱신.
- `media/3d/viewer.html`의 **exercise-media.js, poses.js, viewer.js** 쿼리.
- `media/golf3d/viewer.html`의 **viewer.css, poses.js, viewer.js** 쿼리 및 SW의 해당 4개 자산.
- `samples/pushdown-3d/index.html`의 앱 바로가기 쿼리 및 문서의 대표 최신 링크.
- 푸시다운 전용 `pushdown.js`/`three.min.js`는 현재 쿼리 없이 로드된다. 새 SW 캐시 및 네트워크 우선 정책으로 관리한다. 이 파일 자체를 수정할 때는 실제 새 코드 로딩까지 확인한다.

옛 **“5곳만 bump” 스니펫은 더 이상 충분하지 않다.** 읽지 않은 파일에 무차별 정규식 치환을 하지 말고 위 경로를 확인한다.

- **seed 콘텐츠만** 변경하면 날짜 쿼리로 새로 받아오므로 JS/CSS 자산 버전 bump는 필수 아님. 다만 시각 자료도 바꿨다면 자산 버전을 올린다.
- **핸드오프 등 문서만** 수정하면 seed/자산/SW 버전은 그대로 둔다.
- GitHub 프로젝트 사이트이므로 앱 URL과 파일 참조는 상대경로를 유지한다.
- 변경 확인 → 관련 검증 → 의도한 파일만 stage → `git diff --cached --check` → 한국어 커밋 → `git push origin main` → 라이브 확인.
- remote가 앞서 push가 거절되면 fetch 후 차이를 확인하고 정상 merge/rebase 흐름으로 통합한다. 강제 push로 덮어쓰지 않는다.
- git identity가 이미 있으면 바꾸지 않는다. 과거 author는 `apark`였다.

캐시 동작:

- SW는 네트워크 우선, 성공 응답만 캐시. 실패 시 정확한 URL 캐시 → 동일 origin에서 쿼리 무시 캐시 → 탐색 요청만 index fallback.
- 셸·seed·공통3D코드·Three.js·기존 푸시다운 자산은 선캐시한다. **새 큰 이미지는 방문 시 캐시**하므로 처음 보려는 이미지에는 연결이 필요하다.
- 새 SW는 skipWaiting/clients.claim. 앱은 updateViaCache:'none'로 SW를 갱신하고 기존 제어기가 있던 화면은 controllerchange 때 한 번 새로고침한다.
- Chrome에서 확인하는 것이 실제 사용 흐름이다. 과거 카카오 인앱에서 오래된 버전이 계속 보였고 “다른 브라우저로 열기 → Chrome”으로 해결했다. 웹뷰별 SW 지원·캐시 동작을 단정하지 않는다.
- GitHub 장애로 배포가 지연된 적이 있다. Pages 배포/Actions check 상태와 GitHub Status를 확인한다. 로컬 수정 오류로 오인해 불필요하게 코드를 바꾸지 않는다.
- 빈 커밋 재배포는 과거 장애 복구 후 사용자 요청으로 사용한 방법이다. 장애 동안 무한 재시도하지 않는다.
